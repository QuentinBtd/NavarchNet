# API v1

Base path: `/api/v1`. JSON requests and responses. All routes require `Authorization: Bearer <access-token>`. All non-GET/HEAD requests require the server-side administrator role. Authentication failure is 401; read-only mutation is 403. Schema/malformed bodies are rejected by Axum; business conflicts are 409. Database failures currently use a sanitized 409 response; distinguishing not-found, transient database failure and topology conflict with stable error codes is remaining work.

Routes:

After a saved source candidate, an independent attachment-subnet diagnostic reuses A's existing `vpc-route-lookup` GET for the captured reported attachment subnet and one blank-initially, operator-supplied IP, distinct from original outbound destination D. It is a hypothetical table inspection, not a reverse-flow/traffic-AZ selection or another mandatory forward hop. Exact immutable source topology identity, the scoped A callback, inherited source completion context, copied unique subnet/VPC associations and strict existing response/query/false fields bind the display. `VpcLookupResponse` does not separately echo account/completion time; no fields are invented. Local/blackhole/unresolved and reported target metadata stop there without recursive NAT/IGW queries. No new endpoint, permission, backend rule, host membership, whole-CIDR coverage or return/forward connectivity acceptance is added.

The source/target diagnostic also reuses the existing NAT-reference GET explicitly for each reported target-subnet NAT entry in the chosen network registration. The source account remains displayed; network lookup URLs and literal registration AWS-account metadata bind to the captured network snapshot/time, target response and complete original subnet entry. All returned subnet evidence stays visible, including shared NAT IDs and blackholes, with traffic AZ not inferred. Missing/ambiguous registration provenance disables that continuation with guidance rather than borrowing the source account or granting ownership. There is no automatic query, new endpoint/permission, routeTableId follow-up, healthy-hop or complete-path inference.

The saved VPC lookup UI now offers an explicit `nat-reference-lookup` action only after a reported NAT entry. It sends the captured subnet/destination, not a NAT ID. Joined display requires the saved registration/snapshot/completion time, exact original entry and query, `reference_only: true`, exact false execution/connectivity markers and matching raw-record identity/factual scopes. It reuses the lazy metadata inspector without another fetch. Inputs/resubmit/account/view/session changes retire dependent evidence and retained handlers. This bounded saved-record browser journey adds no endpoint, permission, routeTableId resolution, ownership validation or usable-path/egress/health claim; the API semantics below are unchanged.

For current NAT decoding it holds the literal optional `route_table_id` plus `addresses: NatGatewayAddress[] | null`; each tuple retains optional public/private IPs, allocation/association/interface references, AZ name and ID, primary boolean and status. Null metadata covers legacy/non-NAT rows; null addresses means omitted/unreported, distinct from an explicit empty list. This field does not establish a usable NAT/route-table link, target health, selected flow AZ or measured public egress; no new endpoint, write or permission is added. The saved-topology inspector displays these tuples lazily with snapshot/time and exact false markers, explicit missing/empty/legacy states, inert unvalidated references and bounded DOM continuation. It does not select successful/primary tuples as actual egress or add any fetch/mutation action.

## Saved source-to-TGW CIDR reader API

`GET /aws/accounts/{id}/tgw-source-cidr-coverage?network_account_id=...&subnet_id=...&destination_cidr=...` is protected by the existing role-wide reader/admin authentication. The decoded path ID is the sole source registration; only the three required query fields are accepted. Unknown/missing/duplicate fields, including equal-valued duplicates or encoded aliases, receive framework 400 rejections. Budget/source-account overrides are not supported. The shared core validator rejects noncanonical CIDRs or invalid literal IDs with typed 422 `invalid_query` before either database read, without trimming, repairing host bits or inferring an AWS account. Existing 2048-byte ID and 64-byte canonical CIDR bounds apply after extraction, not as a transport URI/allocation limit. Authentication precedes extraction and sensitive reads; GET also has Axum's ordinary HEAD behavior. This adds no per-account ACL or ownership grant.

The handler performs two `aws_saved_observation_bounded` reads, subtracting the first actual charged text count with checked arithmetic from the default aggregate allowance before the second. Both independently captured observations move into the unchanged composition. It returns that exact already-counted compact JSON envelope directly, without a late wrapper, renamed fields or another provenance object. Each side retains public registration, saved row/generation and typed observation metadata; private role configuration, ExternalId, adoptions and derived topology projections are not read. Incomplete observations can produce complete partitions of unresolved decisions. The same registration may be selected twice, still with two independent charged captures, not a simultaneity or cloud-freshness guarantee. No SDK/provider-enabled check or cloud call is required.

Known saved-reader failures use stable bounded JSON `error` strings: 404 `saved_observation_unavailable`; 413 `saved_observation_budget_exceeded`; 409 `saved_observation_malformed` or `saved_observation_identity_unavailable`; defensive invalid-input 422 `invalid_saved_registration_input`; trusted-budget misconfiguration 500 `saved_observation_budget_configuration_invalid`. Other store failures are redacted to 409 `saved_observation_read_failed`, never raw SQL/payload details. Core errors retain their tagged shape: invalid query 422, budget excess 413, identity/proof unavailable 409. Authentication is 401; extraction remains framework-defined. All refusals return no successful coverage prefix. HTTP body bytes use the core's 4,194,304-byte cap; SQL text/evidence/work/clone bounds remain separate and do not bound HTTP framing, CPU/RSS or deadlines. The optional consumer below leaves HTTP serialization and permissions unchanged. This API does not establish target/NAT/return/full-path/health/authority/live-AWS acceptance.

## Exact saved source-to-TGW CIDR composition core

`aws::source_handoff_cidr_coverage::analyze` consumes two bounded saved captures and an explicit source registration, network registration, source subnet and canonical IPv4/IPv6 destination CIDR. This is a typed library boundary, not a new HTTP endpoint, exported frontend contract or UI. The caller carries the first saved read's charged text bytes into the second read's remaining allowance. Pure callers receive identity/false-marker checks but constructed Rust values are not authenticated database-origin proof. Captures retain separate public registrations, saved row IDs, generations, timestamps, limitations, request IDs and complete original typed observations once per side. They are independent, not simultaneous or necessarily current cloud state.

The collector includes every intersecting source VPC route, source reserved-service predicate and network TGW route on every reported TGW table before any point decision. Predicate provenance uses original side/resource/route indexes, or the fixed VPC service-policy index, with query/enter/leave edges, clipped starts and all coincident raw origins. It does not prune tables using the first witness or zip independently sampled partitions. Scope/readiness/association/subnet/AZ and malformed/prefix-list poison are destination-invariant; every remaining membership predicate is constant inside a cell. The unchanged `source_handoff::lookup` runs once per proved-uniform inclusive cell, preserving alternate gateways/tables, historical TGW literals, unknown precedence and mixed attachment-error order. There is no address enumeration or arbitrary sampling. `partition_complete` means complete existing point-decision coverage, including unresolved/blackhole/non-TGW decisions, not a usable path.

Trusted defaults cap source/network/combined resources at 1000/1000/2000; combined associations, related IDs and TGW table links at 4096 each; VPC plus TGW routes at 512; targets and route attachments at 2048 each; resource CIDRs at 4096; other metadata/tag/address entries at 8192; individual UTF-8 strings at 2048 bytes and regions at 64. Complete typed evidence is compact-JSON counted against 2,097,152 bytes before witnesses. Raw duplicate origins are limited to 2048 and intervals to 256. All input collections, including irrelevant metadata, are admitted rather than silently filtered or repaired.

Logical work reserves `64*B + I*64*(B + Rn*Ln + G) + 64*(Q+I)` against 16,000,000 units before the first point call: `B=1+R+A+L+K+N+T+H+C+M` counts both observations' resource, association, related-ID, table-link, route, target, route-attachment, CIDR and other-entry collections; `Rn/Ln` are network resources/related IDs, `G` is source-region hyphen count plus one, `Q` raw origins and `I` intervals. Aggregate attempted/discarded point-string payload reserves `I*(D*(3*Us+10+Hn)+117)` against 8,388,608 bytes, where `D` is the trusted individual-string cap, `Us` source subnets and `Hn` network route attachments. This covers shared-table-ID fan-out, not just the eventual serialized result. These are conservative logical collection/index/clone/sort-input reservations, not primitive comparison counts, allocator operations, CPU/RSS/deadline or AWS quotas.

The entire compact JSON envelope, including both captures, query, provenance, interval decisions and flags, is limited to 4,194,304 bytes. Borrowed complete evidence is counted once; each private cell is counted once with exact array punctuation before insertion, avoiding repeated growing-prefix serialization. Owned captures/query move into the same serialized envelope shape. Any identity, proof or budget failure returns an error, never a successful prefix; no later uncounted response wrapper is included. This does not supply source-host identity, attachment-subnet routing, target/NAT/return composition, health, traffic-AZ/egress/ownership/authority, live AWS or full-path validation. Execution/connectivity remain false and reference-only remains true.

## Library-only bounded saved-observation reader

`Store::aws_saved_observation_bounded` is a library prerequisite for future multi-observation CIDR analysis, not a new HTTP endpoint or a change to existing lookup handlers. Unlike the existing topology view, it reads no adoptions/private role configuration and derives no subnet-route-table projection. One repeatable-read, read-only transaction captures the latest saved generation and its public registration. A newer attempted discovery does not hide the last saved row. Separate calls, including the same registration twice, are independent captures, never simultaneous snapshots or a perpetual freshness guarantee.

Trusted local defaults admit at most 1,048,576 bytes of decoded topology JSONB text, 16,384 bytes of public-registration JSONB text, 8192 scalar-identity text bytes and 2,097,152 combined text bytes. SQL uses UTF-8 `octet_length(...::text)`, not compressed storage size, and returns NULL for every variable-length payload when any cap fails, before client deserialization. The reader checks that executed gate on refusals. The returned `admitted_bytes` charges the selected JSON and scalar text against a caller's remaining multi-read allowance; it is not a serialized response, wire-framing, memory, PostgreSQL CPU or deadline bound. No HTTP budget override is introduced.

Required typed public/topology identities are cross-checked against registration/scalar account, region, saved row ID and positive generation, with execution/connectivity flags explicitly false. Missing/malformed schemas and mismatches fail without repair. Incomplete supported-query metadata and other uninterpreted typed evidence remain unchanged for the future interpreter rather than being relabeled complete. Private ExternalId is not read or returned. This returns the existing typed observations, not byte-identical arbitrary unknown JSON fields. Consumers still need aggregate collection/work admission, complete CIDR boundary proof and whole-response byte checks. No composed CIDR decisions, new UI/API/permissions, ownership grant, routing or network/connectivity validation is delivered by this reader alone.

## Saved per-table TGW destination-CIDR decisions

`GET /aws/accounts/{id}/tgw-cidr-coverage?route_table_id=...&destination_cidr=...` is an authenticated reader-accessible, SDK-off analysis of the latest immutable saved observation. Only these two query keys are accepted. The literal table ID must be nonempty/control-free and at most 2048 UTF-8 bytes; the network CIDR must be canonical IPv4/IPv6 and at most 64 bytes. New query host bits, whitespace and alternate spellings are rejected, not repaired. Historical TGW route literals retain the existing point interpreter's parsing, including accepted host bits and original textual spelling; VPC reserved-service or stricter historical-CIDR policy is not imported.

The response binds registration, topology ID, start/completion timestamps, AWS account, region, exact table/CIDR inputs, completeness, limitations and request IDs, with `reference_only: true` and both execution/connectivity flags exactly false. `coverage` contains the destination CIDR, `partition_complete: true`, ordered disjoint inclusive address intervals with each existing `TgwLookupResult`, plus `table_evidence` and `parent_evidence` arrays. Each evidence entry preserves its resource-array index and complete original resource; duplicates, null/unqueried collections, original relationship/route/attachment order and uninterpreted metadata are not silently normalized away. Missing/ambiguous/unqueried/foreign/unready scope remains an unresolved decision, not missing output. The partition need not be minimally coalesced.

Only parsed route-network membership varies with destination in the current TGW point interpreter. Every intersecting same-family membership start and inclusive-end successor is collected before evaluating any left endpoint, with no successor beyond the query maximum. These cuts fix candidate membership and hence longest prefix, unknown-type-before-static precedence, static preference, ambiguity, winning state and attachment decisions throughout each interval. Scope/owner/readiness and prefix-list/malformed global poison are destination-independent. Future destination predicates must extend this proof or disable coverage. There is no address enumeration, arbitrary sampling, inferred BGP priority, automatic ingress/source/target composition or UI in this slice.

Fixed trusted local limits are 10,000 resources, 10,000 aggregate related IDs, 10,000 TGW association/propagation links, 1024 TGW route rows across all tables, 4096 nested route attachments, 1,048,576 relevant field bytes, 4096 raw cut insertions including duplicates, 2048 intervals, 1,000,000 logical collection-visit work units and 2,097,152 serialized response bytes. This conservative logical policy is not an instruction/string-comparison/CPU/memory/deadline guarantee or AWS quota. Existing saved-body admission also applies; callers cannot override limits. Malformed/duplicate/missing/unknown query keys return 400, invalid table/canonical CIDR inputs typed 422, input/work/output excess typed 413, and unavailable proof or sanitized storage failure 409. Errors contain no successful partition prefix. Complete decision coverage, including all-unresolved coverage, is not usable routing, ownership/authority, freshness, attachment/target health, traffic AZ, egress, forwarding/return connectivity or a complete path. No AWS/provider call, mutation, plan, adoption, audit write or network probe occurs.

- `GET /aws/accounts/{id}/tgw-target-lookup?transit_gateway_id=...&target_attachment_id=...&destination=...`: authenticated SDK-off reader access to all declared target VPC-attachment subnet entries in one latest saved observation. Returns its exact topology ID/completion time, unchanged inputs, `az_selection: "not_inferred"`, and execution/connectivity flags false. Requires complete supported-query coverage in an explicitly supported region; a unique ready gateway owned by this account; a unique ready attachment whose VPC owner matches this account and whose sole TGW reference equals that gateway; one owned ready VPC; and every declared attachment subnet uniquely present/available/owned in that VPC with canonical IPv4 support and distinct standard AZ IDs. Unknown/duplicate/malformed/foreign evidence is unresolved rather than skipped. Shared/foreign target-VPC ownership is not completed by guessing another account. Reports each subnet's existing strict VPC lookup, preserving main/explicit selection, blackholes and unresolved association/entry evidence. No default or source-matched traffic AZ is guessed: appliance/flow/cross-AZ behavior is outside these saved fields. Up to 32 declared subnets are analyzed; excess returns `target_subnet_budget_exceeded`, never partial results. This is a local work budget, not an AWS service limit. Gateway/attachment inputs over 2048 UTF-8 bytes and destination over 64 bytes fail; query keys are strict. Callers composing with a source response must match this topology ID to its network topology ID before combining evidence. No AWS request, DB/audit/plan write, ownership grant, NAT/public-IP/IGW health resolution, return/SG/NACL/DNS path or measured connectivity occurs. The saved source diagnostic offers an explicit choice only among its reported TGW route attachment references, then reads target entries in the same network registration. It requires matching network topology ID/completion time, gateway/attachment/destination, exact false flags and not-inferred AZ marker before showing all reported entries. Changed snapshots require refresh; resubmit/input/account/session changes retire stale panels. A bounded real current-server/PostgreSQL browser case verifies this composition without response mocks, not a selected AZ or full path. A reported NAT reference does not require or infer a zonal public subnet; regional NAT remains a separate routing model.

The topology view also includes computed `subnet_route_tables`: explicit subnet associations take precedence over implicit main-table selection. A selection requires one unambiguous, owner-matching VPC/subnet/table and an `associated` association state. Incomplete, conflicting, transitioning, foreign or legacy unknown-state records return a typed unresolved reason. This selects reported associations only, not an effective packet path, safe plan or connectivity result. The calculation never rewrites the immutable snapshot; legacy snapshots deserialize missing association state as unknown.

TGW table resources also include typed `tgw_associations`, `tgw_propagations` and `tgw_routes`. `null` means not queried in that observation, while `[]` means a completed empty read. Relationships preserve attachment/resource/type/state/announcement metadata without inferring ownership or readiness. Route searches request static and propagated types, retain CIDR/prefix-list/type/state/announcement and nested attachment metadata, follow bounded continuation tokens, and require explicit consistent completion markers. Truncation, missing collections/markers, cycles, duplicate destinations/type and malformed CIDRs fail discovery rather than publishing partial data as complete. Capture and persistence separately limit relationships, routes and route attachments to 10,000 each; all scoped calls share the EC2 raw-response byte budget. Historical missing fields remain unknown, not retroactively completed. The UI labels reported transitions, unqueried data and unresolved prefix lists explicitly. These observations and per-table calculations do not establish effective end-to-end forwarding.

AWS timestamps are UNIX seconds encoded as strings. Accounts are capped at 500; observations/consents at 10,000 resources and persisted snapshots at 32 MiB. These are hard admission limits, not cursor pagination. The frontend initially renders 200 resources and explicitly offers more. See [onboarding](aws-onboarding.md) for query coverage and unsupported topology.

The saved AWS table card offers a destination-IP lookup to authenticated readers without enabling SDK discovery or writes. The UI binds the response to the displayed snapshot/table/destination and rejects unexpected execution/connectivity flags. A newer snapshot requires refresh; account/view/session changes discard late responses. This is an offline query, not a network probe, route change or end-to-end path calculation.

The authoritative typed JSON structures live in Rust `domain` and `api`; `cargo run --locked --bin export-types` generates `frontend/src/generated.ts`. CI compares regeneration byte-for-byte and type-checks the UI. This prevents structural type drift, not every semantic contract regression; API/browser tests provide independent behavior checks.

`Fault` scenarios are `none`, `throttle`, `persistent_throttle`, `eventual_consistency`, `credential_expiry`, `permission`, `partial_failure`. These simulate provider outcomes; no AWS call or real session expiry is exercised. A probe measurement ingestion route is deliberately not exposed until its authentication/replay/versioning contract is implemented.
