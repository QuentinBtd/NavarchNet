# API v1

Base path: `/api/v1`. JSON requests and responses. All routes require `Authorization: Bearer <access-token>`. All non-GET/HEAD requests require the server-side administrator role. Authentication failure is 401; read-only mutation is 403. Schema/malformed bodies are rejected by Axum; business conflicts are 409. Database failures currently use a sanitized 409 response; distinguishing not-found, transient database failure and topology conflict with stable error codes is remaining work.

Routes:

Saved topology resources include additive `nat_gateway: NatGatewayMetadata | null`. For current NAT decoding it holds the literal optional `route_table_id` plus `addresses: NatGatewayAddress[] | null`; each tuple retains optional public/private IPs, allocation/association/interface references, AZ name and ID, primary boolean and status. Null metadata covers legacy/non-NAT rows; null addresses means omitted/unreported, distinct from an explicit empty list. Unknown status/reference values remain literal, absent booleans/mode stay unknown, and AZ names are not translated. Existing flat IP arrays remain metadata, including non-success statuses. This field does not establish a usable NAT/route-table link, target health, selected flow AZ or measured public egress; no new endpoint, write or permission is added. The saved-topology inspector displays these tuples lazily with snapshot/time and exact false markers, explicit missing/empty/legacy states, inert unvalidated references and bounded DOM continuation. It does not select successful/primary tuples as actual egress or add any fetch/mutation action.

- `GET /snapshot`: bounded accounts/inventory/networks (up to 500 each), plans/operations (100 recent each), auth mode and effective role. Counts describe returned rows, not total historical database rows. No cursor pagination yet.
- `POST /accounts`: `{name, provider:"fake", role_arn:"fake:..."}`. This executable simulation catalog rejects AWS; real read-only role registration uses the separate `/aws/accounts` catalog.
- `POST /accounts/{id}/discover`: synthetic VPC/subnet/route ownership discovery; increments inventory revision.
- `POST /networks`: `{name}` creates the fixed two-AZ eu-west-1 simulated network/policy.
- `POST /plans`: `ConnectionRequest` with account, VPC, subnet IDs, network and `allow_application_traffic:false`. Returns an immutable plan, actions, versions and digest. Unsupported network/subnet replacement after first apply is rejected.
- `POST /plans/{id}/apply`: `{fault:"none"}` or an explicit fake scenario. Returns the durable operation; repeating the same plan returns the same operation. This is idempotency by immutable plan identity, not an arbitrary client idempotency-key feature.
- `GET /operations/{id}`: durable operation status, current step, current-step attempt count and sanitized provider error.
- `GET /operations/{id}/observation`: calculated simulated path, example TEST-NET public IPs, isolation statement, simulated configuration/drift and active-probe status explicitly untested.
- `GET /operations/{id}/events`: ordered bounded step events (1000) including fence and timestamp.
- `POST /operations/{id}/demo-drift`: demo-auth administrators only; removes one fake managed effect after execution is terminal. Reports drift, does not repair it.
- `GET /audit`: most recent 1000 append-only actor/event/target/timestamp records.

## AWS read-only catalog

`GET /snapshot` also returns `aws_read_only_enabled`, `aws_regions` and `aws_accounts`. These do not change the fake planner/provider. All routes below require authentication; POST additionally requires administrator authorization. Disabled access rejects writes before constructing SDK sessions; reads of saved metadata still work.

- `GET /aws/accounts`: up to 500 public account/region registrations, including role ARN, verified identity and requested session attribution. ExternalId and credentials are never returned.
- `POST /aws/accounts`: `RoleRegistration` with `name`, exact `role_arn`, allowlisted `region`, and optional `external_id`. Unknown fields (including permanent access keys) are rejected. STS AssumeRole/GetCallerIdentity must verify the exact account/role before persistence. This verifies identity, not every EC2/RAM permission.
- `POST /aws/accounts/{id}/discover`: bounded read-only STS/EC2/RAM scan, with an audited discovery generation. A failed, incomplete, timed-out or superseded scan never replaces the prior completed snapshot. Request/response identities must match the selected account and region. No database transaction is held during cloud reads.
- `GET /aws/accounts/{id}/topology`: immutable latest completed `AwsTopology` plus append-only metadata-consent records. `complete_for_supported_queries` means only the documented implemented queries, not complete AWS topology. `execution_enabled` and `connectivity_tested` remain false; discovered resources remain `managed:false`. Reported IPs are not measured egress.
- `GET /aws/accounts/{id}/tgw-route-lookup?route_table_id=...&destination=...`: authenticated read-only, offline per-table destination lookup over the latest saved snapshot, with snapshot identity and execution/connectivity flags always false. It does not call AWS or resolve an end-to-end path. It uses longest-prefix selection separately for IPv4/IPv6 and static-over-propagated precedence; reports a blackhole or reported attachment IDs only with known state and unambiguous evidence. Missing owner/readiness/route coverage, unresolved prefix-list entries, equal competing routes, malformed data and unknown route types return a typed unresolved reason. BGP priorities, hidden backups, attachment readiness, ingress association, SG/NACL, NAT/return paths and actual reachability are not inferred. Query keys are strict; oversized inputs fail.
- `GET /aws/accounts/{id}/tgw-ingress-lookup?ingress_attachment_id=...&destination=...`: authenticated offline lookup from an observed VPC attachment, including when SDK access is disabled. Selects the attachment's single reported associated TGW table, never a propagation or an assumed default, then runs the existing per-table lookup. Returns the saved topology identity, exact input values, and execution/connectivity flags always false. A reported association requires an available attachment with a VPC ID, one available observed gateway owned by this snapshot's account, uniquely scoped tables with completed association reads, and one `associated` matching VPC link. A shared VPC's owner may differ from the gateway owner; this grants no ownership or execution rights. Incomplete, unknown, conflicting, malformed or transitioning association evidence returns a typed unresolved result. The nested lookup can independently be unresolved or report a blackhole. This is only the TGW ingress/table leg: no source-subnet/AZ enablement, target readiness, prefix-list expansion, SG/NACL, NAT, return routing, live freshness or end-to-end connectivity is inferred. No AWS requests, plans or snapshot writes occur. Unknown query keys are rejected; attachment IDs over 2048 UTF-8 bytes or destinations over 64 bytes fail.
- `POST /aws/accounts/{id}/adoptions`: `AdoptionConsent` with current `topology_id`, `resource_kind` (`vpc` or `transit_gateway`), exact `resource_id`, and non-empty reason (at most 1000 UTF-8 bytes). Requires current completed discovery and matching resource owner. Foreign/shared/unknown-owner resources are rejected. Exact actor/reason/snapshot repetition is idempotent; existing consent cannot be silently overwritten. This grants metadata consent only, not permission to alter routes or AWS resources.
- `GET /aws/accounts/{id}/vpc-route-lookup?subnet_id=...&destination=...`: authenticated reader-accessible offline lookup in the latest saved snapshot, even with the SDK disabled. Reuses the strict explicit/main subnet-table selector and additionally requires reported `available` VPC/subnet state. The response binds the topology/subnet/destination, selected table and association source; execution/connectivity flags are always false. Nested `reported_route` means only a selected saved CIDR row and its reported target, not that packets actually reach it. IPv4/IPv6 longest-prefix selection is independent; known static origins beat VGW propagation at identical prefixes. Equal competitors, unknown origins (including unmodeled VPC Route Server advertisements), unknown state, malformed/noncanonical CIDRs and unexpanded prefix lists are unresolved rather than silently skipped. A winning blackhole never falls back. Active targets are limited to single well-formed TGW, NAT gateway, internet gateway or `local` references; other/multiple targets remain unsupported. AWS-reserved service ranges are unresolved rather than classified as default egress. Unknown query keys are rejected; subnet IDs over 2048 UTF-8 bytes and destinations over 64 bytes fail. No AWS calls, DB writes, plans, target-health checks, public-IP derivation or forwarding/return-path/SG/NACL/DNS/endpoint reachability claims occur. Saved subnet cards expose this API to readers, bind displayed responses to snapshot/subnet/destination/table/source, discard changed views/sessions and require explicit false execution/connectivity flags. A dedicated real-browser journey covers bounded synthetic saved observations, not live AWS or full-path acceptance.

- `GET /aws/accounts/{source_id}/tgw-source-lookup?network_account_id=...&subnet_id=...&destination=...`: reader-accessible offline composition of two saved account observations, including with SDK access disabled. Returns both exact snapshot IDs and independent completion timestamps, the network registration ID, exact subnet/destination, the existing source VPC lookup and a handoff result; execution/connectivity flags are always false. A `reported_candidate` requires a reported source TGW target, complete network coverage in the same supported region, one unambiguously scoped VPC attachment whose VPC owner matches the source account, and all declared attachment subnets uniquely observed/available in that source VPC/account with canonical IPv4 support and distinct standard AZ IDs. The source subnet's reported AZ ID must match one of them; account-specific zone names and guessed Local Zone parents are not used. The existing ingress primitive then requires the owner-matching ready gateway and reported table association, with the parent bound to the exact unique declared TGW reference. Its nested route lookup may still be a blackhole or unresolved. Non-TGW source entries remain visible but do not invent a TGW handoff. Unknown/ambiguous/foreign/incomplete scope fails closed. Network/subnet IDs over 2048 UTF-8 bytes and destinations over 64 bytes fail; query keys are strict. These are independent latest saved reads, not simultaneous cloud observations or freshness guarantees. No AWS call, write, plan, ownership grant, attachment-subnet/return-route validation, SG/NACL/DNS/endpoint/target-health check or measured/full-path claim occurs. Saved subnet cards expose this through a lazily opened source/network diagnostic: both independent snapshots/times stay visible, source/table/association/network/destination and exact false flags are bound, input changes clear old results, and account/session changes discard late replies. The bounded real-browser fixture uses synthetic cross-account/two-AZ dual-stack metadata and actual production HTTP/PostgreSQL, not response mocks or measured IPv6/egress acceptance.

- `GET /aws/accounts/{id}/tgw-target-lookup?transit_gateway_id=...&target_attachment_id=...&destination=...`: authenticated SDK-off reader access to all declared target VPC-attachment subnet entries in one latest saved observation. Returns its exact topology ID/completion time, unchanged inputs, `az_selection: "not_inferred"`, and execution/connectivity flags false. Requires complete supported-query coverage in an explicitly supported region; a unique ready gateway owned by this account; a unique ready attachment whose VPC owner matches this account and whose sole TGW reference equals that gateway; one owned ready VPC; and every declared attachment subnet uniquely present/available/owned in that VPC with canonical IPv4 support and distinct standard AZ IDs. Unknown/duplicate/malformed/foreign evidence is unresolved rather than skipped. Shared/foreign target-VPC ownership is not completed by guessing another account. Reports each subnet's existing strict VPC lookup, preserving main/explicit selection, blackholes and unresolved association/entry evidence. No default or source-matched traffic AZ is guessed: appliance/flow/cross-AZ behavior is outside these saved fields. Up to 32 declared subnets are analyzed; excess returns `target_subnet_budget_exceeded`, never partial results. This is a local work budget, not an AWS service limit. Gateway/attachment inputs over 2048 UTF-8 bytes and destination over 64 bytes fail; query keys are strict. Callers composing with a source response must match this topology ID to its network topology ID before combining evidence. No AWS request, DB/audit/plan write, ownership grant, NAT/public-IP/IGW health resolution, return/SG/NACL/DNS path or measured connectivity occurs. The saved source diagnostic offers an explicit choice only among its reported TGW route attachment references, then reads target entries in the same network registration. It requires matching network topology ID/completion time, gateway/attachment/destination, exact false flags and not-inferred AZ marker before showing all reported entries. Changed snapshots require refresh; resubmit/input/account/session changes retire stale panels. A bounded real current-server/PostgreSQL browser case verifies this composition without response mocks, not a selected AZ or full path. A reported NAT reference does not require or infer a zonal public subnet; regional NAT remains a separate routing model.

The topology view also includes computed `subnet_route_tables`: explicit subnet associations take precedence over implicit main-table selection. A selection requires one unambiguous, owner-matching VPC/subnet/table and an `associated` association state. Incomplete, conflicting, transitioning, foreign or legacy unknown-state records return a typed unresolved reason. This selects reported associations only, not an effective packet path, safe plan or connectivity result. The calculation never rewrites the immutable snapshot; legacy snapshots deserialize missing association state as unknown.

TGW table resources also include typed `tgw_associations`, `tgw_propagations` and `tgw_routes`. `null` means not queried in that observation, while `[]` means a completed empty read. Relationships preserve attachment/resource/type/state/announcement metadata without inferring ownership or readiness. Route searches request static and propagated types, retain CIDR/prefix-list/type/state/announcement and nested attachment metadata, follow bounded continuation tokens, and require explicit consistent completion markers. Truncation, missing collections/markers, cycles, duplicate destinations/type and malformed CIDRs fail discovery rather than publishing partial data as complete. Capture and persistence separately limit relationships, routes and route attachments to 10,000 each; all scoped calls share the EC2 raw-response byte budget. Historical missing fields remain unknown, not retroactively completed. The UI labels reported transitions, unqueried data and unresolved prefix lists explicitly. These observations and per-table calculations do not establish effective end-to-end forwarding.

AWS timestamps are UNIX seconds encoded as strings. Accounts are capped at 500; observations/consents at 10,000 resources and persisted snapshots at 32 MiB. These are hard admission limits, not cursor pagination. The frontend initially renders 200 resources and explicitly offers more. See [onboarding](aws-onboarding.md) for query coverage and unsupported topology.

The saved AWS table card offers a destination-IP lookup to authenticated readers without enabling SDK discovery or writes. The UI binds the response to the displayed snapshot/table/destination and rejects unexpected execution/connectivity flags. A newer snapshot requires refresh; account/view/session changes discard late responses. This is an offline query, not a network probe, route change or end-to-end path calculation.

The authoritative typed JSON structures live in Rust `domain` and `api`; `cargo run --locked --bin export-types` generates `frontend/src/generated.ts`. CI compares regeneration byte-for-byte and type-checks the UI. This prevents structural type drift, not every semantic contract regression; API/browser tests provide independent behavior checks.

`Fault` scenarios are `none`, `throttle`, `persistent_throttle`, `eventual_consistency`, `credential_expiry`, `permission`, `partial_failure`. These simulate provider outcomes; no AWS call or real session expiry is exercised. A probe measurement ingestion route is deliberately not exposed until its authentication/replay/versioning contract is implemented.
