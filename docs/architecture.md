# Architecture

NavarchNet is a modular monolith. One Rust process serves a static TypeScript UI and versioned JSON API and runs a PostgreSQL-backed operation executor. PostgreSQL is the only durable coordination dependency. No packet forwarding runs in the controller.

## Modules

- `domain`: typed accounts, inventory, regional networks, policy requests, immutable plans, action prerequisites/postconditions, operations and observations. The planner rejects unsupported topology rather than inventing cloud equivalence.
- `provider`: executable simulation capability boundary. The fake provider returns synthetic inventory and classified failure scenarios; this planner/executor rejects AWS. The separate `aws` module supports explicitly enabled read-only SDK observations and offline diagnostics, never network mutation.
- `store`: migrations, desired connection intent, inventory revisions, immutable plan/audit records, queue claims, scoped serialization and observations.
- `executor`: one bounded action per claim, retry/backoff, lease/fence checks, progress and step-event persistence. Worker loss does not delete queued state.
- `external_effects`: separate offline intent journal and observe-only ambiguous-outcome recovery primitives. Not wired to the fake queue, HTTP admission or an AWS mutating provider.
- `auth` and `api`: explicit demo credentials or RS256 OIDC access-token validation, server-side administrator/read-only authorization, bounded request bodies and bounded list endpoints.
- `frontend`: Vite-built TypeScript with native accessible form controls. Rust-derived types are generated by ts-rs and compared byte-for-byte in CI. No provider data is interpolated as HTML.

## Durable coordination

Plans carry inventory, network-policy and scope versions and a SHA-256 digest over their serialized pre-digest representation. PostgreSQL triggers reject plan/audit/event updates and deletes. These are accidental-write safeguards, not a defense against database administrators.

A connection scope is account + VPC. Applying locks the network, inventory and scope in that order, checks revisions, reserves a scope version and writes an operation plus desired connection atomically. Simultaneous applies of the same immutable plan return the existing operation. A partial unique index permits only one queued/running/retrying operation per scope. Network locking serializes topology overlap validation across accounts. CIDR overlap prevents a new apply.

The queue uses `FOR UPDATE SKIP LOCKED`. Each claim increments a durable fence and obtains a 15-second lease using PostgreSQL's clock. The worker locks network, inventory and operation in the common order, validates revisions, fence, status and lease, executes one fake action and checks lease validity again at commit. A stale worker cannot commit a fake effect or progress. Retryable failures use bounded exponential backoff, maximum five attempts including the initial call. Permission/conflict/topology errors become failed or partial states and retain completed effects. No destructive compensation is attempted.

The fake provider's effect and step progress commit in the same database transaction. This deliberately strong simulator property DOES NOT apply to AWS: a remote mutation can succeed before a controller crash or lease loss. Before AWS execution is enabled, the provider must use client tokens/tags, observe-before-retry, bounded SDK timeouts, a scope lease protocol that accounts for in-flight external effects, and tested recovery for ambiguous outcomes. A database fencing token alone cannot cancel an AWS call.

The offline external-effect journal now persists an immutable scope/action/fingerprint and stable client token before dispatch. A scope reserves one action permanently in this first primitive; replacements/deletion and multi-action plans are not supported. Claims use 1–300-second database-clock leases and increasing fences. The durable `dispatched` marker is committed before returning an in-process permit; reclaiming it permits observation only. Confirmation requires a current live fence plus matching trusted token/fingerprint evidence and a bounded external resource ID. Missing, ambiguous or conflicting evidence cannot reset dispatch or replace intent. Intent identity and event history have database immutability/monotonic-state guards; these remain accidental-write safeguards, not administrator isolation.

This is not exactly-once remote execution. A permit cannot cancel or fence an already issued external request, and a token is useful only if a future provider's exact API supports its semantics. A crash after the marker but before sending a request deliberately leaves an uncertain intent requiring observation/manual recovery; even an absent read never authorizes a blind retry. No production adapter supplies trusted observations yet. The independent replay test commits a resource in a separate local PostgreSQL schema/transaction, actually kills the child process, then recovers by observation without repeating the external mutation. This does not establish live AWS idempotency, ownership, eventual consistency or stale-worker cancellation.

## Supported changes

This preview creates one fake connection and supports idempotent reapplication/repair of missing identical effects. It freezes network/subnet selection after first apply. Network replacement, subnet removal/expansion and deletion are rejected until explicit safe migration actions exist. Managed resource identity excludes plan-local prerequisite indices. Conflicting existing effects become durable partial/failure records instead of infinite retries.

Drift compares current relevant simulated effects with the immutable desired actions. Missing/extra/mismatched effects are reported, never automatically repaired. Rediscovery invalidates plans and queued execution, even when fake discovery happens to return the same synthetic topology. This is conservative by design.

## Measurement boundary

Discovered configuration, calculated route paths, provider resource state and actual data-plane measurements are distinct. No probe agent or automatic failover exists. A future authenticated `/measurements/v1` ingestion boundary must bind probe identity to allowed account/subnet/AZ, enforce schema version, bounded payload, nonce/sequence, freshness and replay protection, and store measurement timestamps separately from controller receipt times. It must not accept unauthenticated heartbeat claims. No endpoint is exposed until implemented and tested.

A probe follows its subnet's effective routing; it cannot select an arbitrary route by pinging. Future failover requires independent confirmation, verified backup readiness, hysteresis/hold-down and explicit return-to-primary. Missing controller heartbeats are not data-plane outage evidence. NAT changes may reset connections or change public IPs.
