# Testing and acceptance boundaries

## Local-first gates and installed hooks

Use mise 2026.9.18 or newer and the exact `.mise.toml`. It pins Rust 1.99.0 (minimal profile plus rustfmt/Clippy), Node 24.22.0, prek 0.5.6 and actionlint 1.7.12. `mise install` installs the selected tools; existing compatible installations can be linked with `mise link` instead of downloaded again. Cargo uses one build job, zero debug information and no incremental compilation. The cache environment honors existing project-scoped CARGO_HOME/CARGO_TARGET_DIR/NPM_CONFIG_CACHE/PREK_HOME overrides and otherwise uses project-owned paths.

1. Run `mise run frontend-install`, `mise run browser-install` and `mise run hooks-install`.
2. `mise run fast` / the actual prek pre-commit hook check workflow syntax/policy, Rust formatting and frontend types/lint/behavior without a PostgreSQL requirement or a Rust dependency build.
3. Set DATABASE_URL to an isolated disposable PostgreSQL 17 database, then run `mise run full` / the actual prek pre-push hook. It runs every Rust test, PostgreSQL migrations/coordination/recovery, Clippy, generated types, locked frontend installation, frontend checks/build, actual HTTP SIGKILL/restart smoke, dependency/license policy and the real browser journey.
4. `mise run unit`, `mise run postgres`, `mise run contract`, `mise run frontend-test` and the other named tasks support targeted iteration. They do not replace the full composed pre-push gate. Missing infrastructure is a failing gate, not an automatic downgrade.
5. `mise run containers` and `mise run package` are separate, explicit deployment/distribution qualifications. They are not silently included or claimed by `mise run full`. The container task requires Docker Compose and ephemeral demo environment values, uses a separate navarchnet-* Compose project and tears down its own disposable volumes. The package task requires a matching native architecture and a real database; it never publishes. Qualify both architectures when changing distribution-sensitive code.

The workflow has only `workflow_dispatch`, with verify/container/packages/all choices. No automatic PR/push heavy builds and no automatic /test comment handler are configured. Actions invoke the same local mise entry points, not a second test implementation. `mise run workflow-check` validates syntax with actionlint and tests that automatic events, mutable action refs, write permissions or missing shared tasks are rejected. Manual qualification still consumes Actions minutes and needs a deliberate maintainer choice; it is not a development build server.

## Source, database and browser tasks

### One current server artifact

`mise run build` reads Cargo's absolute target directory and records the actual `compiler-artifact.executable` emitted by the successful locked build, with its SHA-256, in `navarchnet-current-build.json` inside that target directory. Failed builds remove the prior receipt. HTTP startup, the healthcheck and Playwright all use that same absolute artifact; missing receipts or a changed executable fail rather than falling back to `target/debug/navarchnet`. Relative target overrides are resolved by Cargo from the repository root, not the frontend working directory. Build first when invoking smoke or browser tasks separately.

The source smoke task clears `NAVARCHNET_BINARY`; it must not qualify an unrelated ambient override. Direct packaged-binary smoke intentionally retains that explicit override for `scripts/verify-package.sh`, a separate distribution qualification. Playwright always uses the current Cargo receipt. `mise run binary-contract-test` tests receipt rejection, artifact replacement and literal shell-path quoting; both fast and full gates include it.

`mise run binary-target-regression` is an explicit real-server integration regression, not a fabricated HTTP fixture. Set `CARGO_TARGET_DIR` to a separate directory (spaces are supported), `NAVARCHNET_OBSOLETE_BINARY` to an actual retained server artifact predating `GET /aws/accounts`, and `DATABASE_URL` to real disposable PostgreSQL. The task builds the current source in the alternate target, temporarily places the distinct obsolete binary at the default path, verifies its real database-backed readiness and absent GET contract (405), then runs the unchanged HTTP/crash and browser harnesses, which require the current GET contract (200). A deliberately stale `NAVARCHNET_BINARY` override must not win. Original default artifacts/receipts are restored in cleanup. Serialize this explicit task with every other project validation/build; do not point the obsolete fixture at the only retained copy if another process can overwrite it. Frontend assets and Chromium must already be installed/built, as with the standalone smoke/browser tasks. The regression is local opt-in, not another automatic heavy CI job. Earlier successful default-target gates remain evidence for their original source and configuration, not acceptance of this fix.

`mise run check` (also `sh scripts/check.sh`) is the source/build/crash portion of the full gate. It runs Rust formatting/Clippy, every unit/property/integration test, actual PostgreSQL migrations/coordination/recovery tests, generated Rust/TypeScript contract comparison, locked npm installation, type checking/lint/behavior tests, production frontend build and a real HTTP/process restart smoke. There is no PostgreSQL skip mode. Additional PostgreSQL schema creation privileges are required for isolated integration schemas; never point tests at production.

`npm --prefix frontend run e2e` runs Playwright against the production-built frontend and a spawned Rust server, backed by the same real disposable database. Install Chromium with the pinned Playwright package first. The central journey registers/discovers an account, selects VPC/subnets/egress, reviews/applies a plan, inspects convergence/untested probes, injects drift and observes partial failure. A second browser test checks read-only UI/API authorization. Session unit tests reject delayed responses after logout.

`sh scripts/install-tools.sh deny` and `.local/tools/bin/cargo-deny --locked check` enforce advisory/license/source policy. SECURITY.md documents the single RSA advisory exception and review date. `npm --prefix frontend audit --audit-level=high` fails high/critical npm advisories. `node scripts/notices.mjs --check` verifies generated dependency notices. It is an attribution/component inventory, not a signed or complete standard SBOM/provenance attestation.

`sh scripts/install-tools.sh dist`, `.local/tools/bin/dist build --artifacts=local --target=x86_64-unknown-linux-gnu` and `sh scripts/verify-package.sh x86_64-unknown-linux-gnu` exercise packaging without publication. Set DATABASE_URL for the package verifier to also run the real packaged-binary HTTP/crash smoke. ARM64 uses its own native runner/target; a configured target is not an executed ARM64 test.

## What tests establish

Domain tests establish conservative logical plan ordering/rejection, not actual EC2 route programming. PostgreSQL tests establish immutable records, scope serialization, simultaneous apply idempotency, independent claims, stale-worker rejection, revision invalidation, retry persistence, partial conflicts, drift and reconnect recovery. The HTTP smoke SIGKILLs an unfinished application process, restarts it, waits for durable completion, verifies idempotent reapplication and then checks drift/partial failure. A fake effect and progress commit atomically in PostgreSQL; AWS effects cannot inherit that property.

Independent source review found real lock-order, connection replacement/effect-conflict and logout race defects. Regression tests and conservative unsupported-change rejection address them. The first frontend browser run also found an illegal native fetch binding; it was fixed and the real browser journey rerun. Raw mission validation logs live outside the repository; STATUS.md records the final gate boundary, not an invented coverage percentage.

## Opt-in AWS acceptance — NOT RUN and not implemented as a passing suite

No cloud acceptance workflow or implicit credential-chain invocation is configured. Until SDK discovery/execution and action-level ownership are implemented, the following is a required future acceptance procedure, not an executable success claim.

1. Obtain separate explicit authorization for a disposable network account and two disposable application accounts, one specified region and two AZ IDs. Register exact role ARNs/ExternalIds, spending limits, resource inventory tags and cleanup owner. Capture a cost estimate and baseline resources/routes before mutation.
2. Verify standard-chain controller identity, target AssumeRole identities, role capabilities, RAM organization/invitation flows and attachment acceptance. Test pagination and supported/unsupported ownership/topology. No production account shortcuts.
3. Create or explicitly adopt the approved zonal public managed-NAT regional design. Review each forward/return route and isolation rule. Apply with operation/client tokens and ownership tags.
4. Deploy authorized disposable probe workloads in each application account/AZ. Verify actual IPv4 Internet egress/public IPs and return traffic using independent endpoints. Record results per AZ/account. Check that application A cannot reach B by default; allow shared services only under a separate explicit policy.
5. Reapply and restart controllers mid-operation. Verify no duplicate resources, no old-worker mutations after takeover, bounded throttling/session retries, permission/partial failure recovery and stale-plan invalidation. Inject a bounded manual managed-route change and confirm report-only drift before any repair.
6. Inventory every created/adopted resource and actual billable components. Remove only explicitly test-owned resources in dependency-safe order, preserve pre-existing resources, and verify through a read-back inventory that no NAT/TGW/EIP/compute/share/probe resource remains billable. Document any manual recovery and residual cost.

Attach exact account/region/AZ inventory, command/API evidence, probe outputs, costs and cleanup readbacks to the eventual acceptance report. Do not equate a simulator, API-success response, missing heartbeat or a calculated path with tested connectivity.
