# Testing and acceptance boundaries

## Local-first gates and installed hooks

Use mise 2026.9.18 or newer and the exact `.mise.toml`. It pins Rust 1.99.0 (minimal profile plus rustfmt/Clippy), Node 24.22.0, prek 0.5.6 and actionlint 1.7.12. `mise install` installs the selected tools; existing compatible installations can be linked with `mise link` instead of downloaded again. Cargo uses one build job, zero debug information and no incremental compilation. The cache environment honors existing project-scoped CARGO_HOME/CARGO_TARGET_DIR/NPM_CONFIG_CACHE/PREK_HOME overrides and otherwise uses project-owned paths.

1. Run `mise run frontend-install`, `mise run browser-install` and `mise run hooks-install`.
2. `mise run fast` / the actual prek pre-commit hook check workflow syntax/policy, Rust formatting and frontend types/lint/behavior without a PostgreSQL requirement or a Rust dependency build.
3. Set DATABASE_URL to an isolated disposable PostgreSQL 17 database, then run `mise run full` / the actual prek pre-push hook. It runs every Rust test, PostgreSQL migrations/coordination/recovery, Clippy, generated types, locked frontend installation, frontend checks/build, actual HTTP SIGKILL/restart smoke, dependency/license policy and the real browser journey.
4. `mise run unit`, `mise run postgres`, `mise run contract`, `mise run frontend-test` and the other named tasks support targeted iteration. They do not replace the full composed pre-push gate. Missing infrastructure is a failing gate, not an automatic downgrade.
5. `mise run containers` and `mise run package` are separate, explicit deployment/distribution qualifications. They are not silently included or claimed by `mise run full`. The container task requires Docker Compose and ephemeral demo environment values, uses a separate navarchnet-* Compose project and tears down its own disposable volumes. The package task requires a matching native architecture and a real database; it never publishes. Qualify both architectures when changing distribution-sensitive code.

The workflow has only `workflow_dispatch`, with verify/container/packages/all choices. No automatic PR/push heavy builds and no automatic /test comment handler are configured. Actions invoke the same local mise entry points, not a second test implementation. `mise run workflow-check` validates syntax with actionlint and tests that automatic events, mutable action refs, write permissions or missing shared tasks are rejected. Manual qualification still consumes Actions minutes and needs a deliberate maintainer choice; it is not a development build server.

## Source, database and browser tasks

### One current server artifact

`mise run build` reads Cargo's absolute target directory and records the actual `compiler-artifact.executable` emitted by the successful locked build, with its SHA-256, in `navarchnet-current-build.json` inside that target directory. Failed builds remove the prior receipt. HTTP startup, the healthcheck and Playwright all use that same absolute artifact; missing receipts or a changed executable fail rather than falling back to `target/debug/navarchnet`. Relative target overrides are resolved by Cargo from the repository root, not the frontend working directory. Build first when invoking smoke or browser tasks separately.

The source smoke task clears `NAVARCHNET_BINARY`; it must not qualify an unrelated ambient override. Direct packaged-binary smoke intentionally retains that explicit override for `scripts/verify-package.sh`, a separate distribution qualification. Playwright always uses the current Cargo receipt. `mise run binary-contract-test` tests receipt rejection, artifact replacement and literal shell-path quoting; both fast and full gates include it.

`mise run binary-target-regression` is an explicit real-server integration regression, not a fabricated HTTP fixture. A deliberately stale `NAVARCHNET_BINARY` override must not win. Original default artifacts/receipts are restored in cleanup. Serialize this explicit task with every other project validation/build; do not point the obsolete fixture at the only retained copy if another process can overwrite it. Frontend assets and Chromium must already be installed/built, as with the standalone smoke/browser tasks. The regression is local opt-in, not another automatic heavy CI job. Earlier successful default-target gates remain evidence for their original source and configuration, not acceptance of this fix.
