# Contributing

All code, comments, UI, docs, issues, pull requests and commit messages are in English. Contributions to original NavarchNet code are provided under Apache-2.0; preserve third-party licenses and notices and do not add unsupported rights-holder claims.

Use small vertical slices and Conventional Commits. Write a failing behavior test before implementing meaningful domain changes or defect fixes, then make it pass and refactor. Run `mise install`, `mise run frontend-install`, `mise run browser-install` and `mise run hooks-install` once. The repository-local prek pre-commit hook runs `mise run fast`; the pre-push hook runs `mise run full`. Set DATABASE_URL to a real disposable PostgreSQL database and run the full local gate before requesting review. Missing PostgreSQL/browser prerequisites fail rather than silently skip. Container/native-package qualification has separate explicit mise tasks. No live AWS tests on normal PRs, and do not use Actions for iterative development.

Keep API, domain, store, executor and providers separate within one Rust application. Do not introduce Kafka, Redis, microservices or dynamic plugins for hypothetical scale. Any change to ownership, route isolation, locking order, revision preconditions, retries or execution fencing requires a PostgreSQL regression test and independent source review.

The supported build toolchain is pinned consistently in rust-toolchain.toml and the exact `.mise.toml`; MSRV is the same exact release until a separately reviewed policy changes it. Commit Cargo.lock and frontend/package-lock.json. Use locked installs and regenerate `frontend/src/generated.ts` with `mise exec -- cargo run --locked --bin export-types`. Do not edit generated types manually. Heavy GitHub workflows are workflow_dispatch-only, use pinned action SHAs/read-only permissions and call the same mise tasks; enabling automatic heavy push/PR jobs violates the local-first policy.

No cloud mutations, paid test resources, crates.io/GHCR uploads or release/tag publication without separate explicit maintainer approval. Fake-provider tests are not AWS connectivity evidence. Document both completed gates and missing acceptance criteria in docs/STATUS.md.
